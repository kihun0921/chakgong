# 베타·출시 판정 안내 (Wave 7)

베타는 **관리자가 실제 업체 의뢰 착공계를 이 프로그램으로 만들어 납품하고, 수작업 결과와 비교**하는 단계다.
코드는 측정·기록·판정을 도와줄 뿐이고, 아래 "사람이 할 일"은 사람이 해야 끝난다.

## 1. 베타 진행 순서
1. 배포 준비(`docs/DEPLOY.md`)를 마치고 관리자 계정을 만든다.
2. 베타 일정(시작·종료일)을 정한다. 공사 3건 이상을 목표로 한다(KPI 판정 표본, `MIN_SAMPLE=3`).
3. 의뢰가 오면 **새 공사 만들기 → 내역서 올리기** (이때 북극성 시작 시각이 기록된다).
4. 입력·검증을 마치고 합본·엑셀·PDF를 만든다 (첫 납품 시각이 기록되고 5분 안인지 계산된다).
5. 같은 공사를 수작업으로 만든 결과(또는 걸린 시간)와 비교해 공사 화면의 **베타 기록**에 적는다.
6. 업체가 발주기관에서 받은 **첫 제출 보완 요구 횟수**와 그중 **불일치 원인 횟수**를 알려 주면 베타 기록에 적는다(시스템이 알 수 없는 값, D-11).
7. 용역비는 납품 후 입금 확인을 기록한다(550,000원 후불).
8. 베타 종료 때 `/beta`(베타 종합) 화면으로 판정한다.

## 2. 판정 기준 (PRD 1장, SRS 13.3)
| 지표 | 목표 | 어디서 보나 |
| --- | --- | --- |
| 북극성: 검증 통과 초안 5분 달성률 | 90% 이상 달성 / 50% 미만 피봇 / 그 사이는 개선 후 재측정 | `/beta` (시스템 기록) |
| 보조 1: 서류 간 불일치·집계표 차이 | 납품본 0건·0원 (시스템이 막은 건수는 참고로 표시) | `/beta` |
| 보조 2: 첫 제출 보완 요구 횟수 | 낮을수록 좋음(목표값 없음, 불일치 원인 0회) | `/beta` (관리자 기록) |
| 수작업 대비 시간 | 도구 시간 < 수작업 시간 | `/beta` |

- 3건 미만이면 화면이 "참고용"이라고 표시한다. 판정은 3건 이상에서 한다.
- 피봇 방향은 PRD 1장을 따른다.

## 5. 사람이 할 일 요약 (코드로 대신할 수 없는 것)
1. 샘플 올리기: 기준 내역서, 건축·토목·조경·전기 내역서, 직접시공계획서 양식, 법정 서식 문안 → 올리면 바로 적용한다.
2. Supabase 연결·후이즈 A 레코드·GitHub·나라장터 키 (맨 나중, `docs/DEPLOY.md` 0장).
3. 서버에 올리고 점검 목록 확인(`docs/DEPLOY.md` 5장).
4. 실제 Excel에서 출력 xlsx 열어 보기.
5. 베타 공사를 진행하며 베타 기록 입력, 종료 시 `/beta`로 판정.
