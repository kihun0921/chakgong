# 착공계·공정표·인원장비투입계획 자동화 SRS v1.0

- 작성: EGIGAE 7기 권기훈
- 작성일: 2026-10-17
- 기준 문서: `착공계·공정표·인원장비투입계획 자동화 PRD v0.1.md` (2026-10-17 최종본, 개발 착수 전 미정 항목 없음)
- 문서 체인: VPS(왜) → PRD(무엇을) → **SRS(어떻게 동작해야 하는가, 이 문서)**
- 제공 방식: 관리자가 관리자 계정으로 로그인해 착공 서류를 작성하고 업체에 납품하며, 용역비는 납품 후 무통장입금(후불)으로 받는다. 업체는 시스템에 접근하지 않는다.
- 제공 형태: 별도 서비스로 운영한다. 올케어솔루션 홈페이지(단말기 렌탈·내역 신청 전용)에는 이 프로그램을 메뉴(링크)로만 달며, 올케어안전플랫폼처럼 별도 회원가입·결제 체계를 쓴다. 이 프로그램은 자체 관리자 로그인과 무통장입금 기록을 쓰고 다른 서비스와 연동하지 않는다. 홈페이지 메뉴 추가는 이 SRS의 범위 밖이다.

## 1. 문서 개요

### 1.1 목적

최종 PRD의 Must 기능 F1~F11을 구현하려면 시스템이 어떻게 동작해야 하는지를 시험할 수 있는 문장으로 정한다. 모든 요구사항은 PRD의 기능(F)과 수용 기준(AC)에 연결한다. PRD에 없는 요구는 새로 만들지 않았고, PRD가 정하지 않은 동작은 11장에 '설계 결정'으로 따로 모아 확정했다.

### 1.2 범위

PRD 7장의 In/Out을 그대로 따른다.

| 구분 | 포함 | 제외 |
| --- | --- | --- |
| 입력 | 나라장터 공고 API 또는 파일 첨부, 내역서(xlsx), 공고 PDF(텍스트 추출 가능) | 설계도면(CAD) 해석 |
| 산출 | 예정공정표, 인원·장비투입계획표(xlsx·PDF), 착공계 합본(PDF) | 실행예산 편성, 기성 청구, docx·hwp 출력 |
| 서류 | 공문, 착공신고서, 선임계류, 안전보건관리책임자 선임서, 조직도, 간지, 사진첩, 노무비 합의서, 확약서 | 품질·환경·안전관리계획서 본문(간지만 생성, 본문은 업로드) |
| 공종 | 기계설비, 건축, 토목, 조경, 전기 | 통신 등 그 외 공종 |
| 발주 | 조달청(나라장터) 시설공사, 국가·지방 계약 유형 | 그 외 발주 체계 |
| 사용자 | 관리자(작성·납품·용역비 관리) | 업체(고객사)의 로그인·직접 작성·직접 조회 |
| 제공 형태 | 별도 서비스로 단독 운영(자체 관리자 로그인·용역비 기록) | 올케어솔루션 홈페이지 메뉴 추가, 다른 서비스와의 로그인·결제·데이터 연동 |
| 용역비 | 용역비 550,000원 기록, 무통장입금 확인 기록, 세금계산서 발행 여부·발행일 기록, 환불·취소 기록, 관리자 대시보드 | 온라인 결제(PG·카드), 은행 자동 연동, 세금계산서 발행, 전자 제출·날인, 서류 문서 편집기 |

1차 출시 범위는 Must 전체다. PRD의 Should(2차)·Could(3차) 항목은 이 문서의 12장에 '후속 요구'로만 적고 1차 요구사항 번호는 주지 않았다.

## 2. 시스템 개요

### 2.1 구성

시스템은 올케어솔루션·올케어안전플랫폼과 무관한 별도 웹 서비스다. 관리자가 입력 두 가지(공고번호 또는 공고 파일, 내역서)로 서류 세 묶음(예정공정표, 인원·장비투입계획표, 착공계 합본)을 만들어 업체에 납품한다. 관리자 로그인·권한은 이 프로그램이 자체로 처리하고, 결제 수단은 만들지 않는다(용역비는 무통장입금을 기록만 한다). 자체 주소(도메인)를 가지며 올케어솔루션 홈페이지는 이 주소로 연결하는 메뉴만 단다.

| 구성 요소 | 책임 |
| --- | --- |
| 입력 처리 | 공고 수신, 내역서 파싱, 추출값 확인·확정 |
| 계산 엔진 | 일정·보할·진도율·인원·장비 계산(설정값만으로 동작, 같은 입력이면 같은 결과) |
| 검증 엔진 | 금액·진도율·연인원·서류 간 일치·공기 초과 검사, 출력 차단 판단 |
| 서류 생성 | 템플릿 기반 서류 생성, 합본, 목차·쪽번호 |
| 출력 | xlsx(수식 유지), PDF, 납품 이력 기록 |
| 용역비 관리 | 용역비 기록, 무통장입금 확인 기록, 세금계산서 발행 여부 기록, 환불·취소 처리, 상태 전이 규칙 |
| 관리 | 기준정보, 공사 저장·복제, 관리자 대시보드 |
| 감사·보안 | 이력 기록, 암호화, 마스킹, 권한 검사 |

### 2.2 사용자와 권한

| 사용자 | 할 수 있는 일 | 할 수 없는 일 |
| --- | --- | --- |
| 관리자 | 모든 공사의 생성·입력·가정값 수정·서류 생성·최종 출력(납품), 기준정보 편집, 용역비·입금 기록, 관리자 대시보드 조회 | - |
| 업체(고객사) | 없음. 시스템 사용자가 아니다 | 로그인, 조회, 다운로드, 코멘트 |
| 그 외 사용자(로그인하지 않은 사용자 포함) | 없음 | 프로그램과 공사 화면 접근 |

권한은 서버에서 검사한다. 화면 숨김만으로 권한을 대신하지 않는다. 관리자는 1~3명이며 모든 관리자가 모든 공사를 조회·수정할 수 있다.

### 2.3 운영 환경

웹 브라우저에서 사용한다. 데이터는 클라우드에 저장한다. 동시 사용자는 관리자 1~3명이다.

## 3. 업무 흐름

1. 의뢰 접수(시스템 밖): 업체에서 공고번호, 내역서, 계약·기술인 정보, 첨부 서류를 받는다.
2. 공사 생성: 관리자가 공고번호를 입력하거나 파일을 첨부한다. 공사와 함께 용역비(550,000원, '미입금')가 기록된다.
3. 입력 확인: 추출된 공사 정보·집계표·노무 라인을 보고 수정해 확정한다(확정해야 다음으로 간다).
4. 일정 설정: 착공일, 공기, 공휴일, 공정별 착수·완료일차.
5. 계산: 보할·진도율, 인원·장비 산정. 가정값 수정 시 재계산.
6. 착공계 정보 입력: 업체(시공사) 정보, 계약 정보, 기술인, 공동수급체, 계약 유형, 사진·첨부 업로드.
7. 검증: 검증 규칙을 모두 통과해야 초안이 '검증 통과'가 된다.
8. 초안 확인: 화면으로 공정표·투입계획·서류 미리보기.
9. 최종 출력(납품): xlsx, 공정표·투입계획표 PDF, 착공계 합본 PDF를 만들고 업체에 전달한다(전달은 시스템 밖). 납품 이력이 기록된다.
10. 입금 확인(후불): 업체가 무통장입금하면 관리자가 통장에서 확인해 입금일·입금자명·입금액을 기록한다. 세금계산서는 시스템 밖에서 발행하고 발행 여부·발행일을 기록한다.
11. 변경 시: 업체 요청으로 가정값·착공일을 바꾸면 4~7단계를 다시 거쳐 추가 용역비 없이 재출력한다.

검증 미통과면 출력하지 않고 고친 뒤 다시 검증한다. 입금은 납품 뒤에 일어나므로 최종 출력은 입금과 무관하다.

## 4. 기능 요구사항

ID 규칙: `SR-<영역>-<번호>`. 모든 요구사항은 PRD 기능(F)과 수용 기준(AC)에 연결된다. 우선순위는 PRD의 MoSCoW를 따르며, 이 장의 요구는 모두 Must(1차)다. 동작의 주체는 모두 관리자다.

### 4.1 입력·파싱 — F1

| ID | 요구사항 | PRD 근거 |
| --- | --- | --- |
| SR-IN-01 | 공고번호를 입력하면 나라장터 입찰공고 API를 호출해 공사명, 공사관리번호, 수요기관, 공사현장, 공사기간, 추정금액을 받아 공사 정보에 자동 입력하고, 첨부된 내역서를 수신한다. | F1, AC-F1-1 |
| SR-IN-02 | 공고 PDF(텍스트 추출 가능)를 첨부하면 SR-IN-01의 항목을 추출한다. 스캔본은 수동 입력으로 안내한다. | F1, 6장 인터페이스 |
| SR-IN-03 | 내역서 .xlsx(20MB 이하)를 업로드하면 갑지·원가·집계표·내역서 시트를 인식하고, 집계표에서 공종코드별 재료비·노무비·경비·합계를 추출한다. | F1, AC-F1-2 |
| SR-IN-04 | 내역서의 '노무비' 행에서 직종·수량(인)·노임단가를 공종코드별로 추출하고, 경비 항목 중 장비(예: 크레인, 단위 HR)를 식별해 장비 목록으로 분리한다. | F1, F4 |
| SR-IN-05 | 시트·머리글(공종·품명·규격·단위·수량·재료비·노무비·경비)을 인식하지 못하면 시트명과 열 위치를 매핑 화면에서 지정할 수 있다. 지정한 매핑은 저장해 같은 양식에서 재사용한다(D-13). | F1, AC-F1-2, ADR-3 |
| SR-IN-06 | 추출 결과를 표로 보여 주고, 관리자가 수정해 '확정'을 눌러야만 다음 단계로 진행한다. 확정 전 값은 계산에 쓰지 않는다. | F1, AC-F1-2 |
| SR-IN-07 | 나라장터 API 호출이 실패(오류, 시간 초과, 이용 불가)하면 실패 사유를 표시하고, 이미 입력한 값을 유지한 채 파일 첨부·수동 입력으로 끝까지 진행할 수 있게 한다. 호출 시간 제한은 10초로 한다(D-3). | F1, AC-F1-3, ADR-2 |
| SR-IN-08 | 20MB를 넘는 파일, .xlsx가 아닌 파일, 암호가 걸려 열 수 없는 파일은 원인을 알려 주고 거부한다. 입력 원본 파일은 수정 없이 보관한다. | F1, 제약(원본 보관) |

### 4.2 공정 구성·일정 — F2

| ID | 요구사항 | PRD 근거 |

| SR-PL-04 | 모든 관리자는 모든 공사를 조회·수정할 수 있다(공사 소유자 구분 없음, D-12). 개인정보는 관리자에게도 화면에서 마스킹하고, 열람·출력은 이력으로 남긴다. | F9, 보안 |

### 4.10 용역비·입금 관리 — F10

#### 용역비 상태

| 상태 | 의미 |
| --- | --- |
| 미입금 | 공사 생성 시의 기본 상태. 용역비가 청구 대상이며 아직 입금이 확인되지 않음. 납품(최종 출력)은 이 상태에서도 가능 |
| 입금 완료 | 관리자가 무통장입금을 확인해 기록한 상태 |
| 환불 | 입금된 뒤 납품 전에 의뢰가 취소되어 입금액을 환불한 상태 |
| 취소 | 입금 없이 납품 전에 의뢰가 취소된 상태 |

상태 전이: 미입금 → 입금 완료, 미입금 → 취소, 입금 완료 → 환불(납품 이력이 없을 때만). 환불·취소는 마지막 상태이며 같은 공사로 되돌리지 않는다(필요하면 복제한 새 공사로 진행). 납품(최종 출력) 자체는 상태를 바꾸지 않는다.

| ID | 요구사항 | PRD 근거 |
| --- | --- | --- |
| SR-FEE-01 | 공사를 만들면 용역비를 '미입금'으로 기록한다. 금액은 공급가액 500,000원 + 부가세 50,000원 = 합계 550,000원이며 모두 정수(원)다. 금액은 설정 값으로 관리해 코드 수정 없이 바꿀 수 있게 하되, 이미 기록된 공사의 금액은 바뀌지 않는다. 재의뢰·단골·소개 할인이 적용되면 공급가액에만 할인을 반영하고 부가세·합계를 다시 계산해 그 값을 공사에 기록한다(`docs/RETENTION.md` 3장 D·E, SR-FEE-14). | F10, AC-F10-1 |
| SR-FEE-02 | 최종 출력은 용역비 입금 여부와 무관하다(후불). 검증을 통과한 공사는 '미입금' 상태에서도 최종 출력할 수 있다. | F10, AC-F10-1, 용역비(후불) |
| SR-FEE-03 | 관리자가 입금 확인을 기록하려면 입금일·입금자명·입금액이 모두 필요하다. 입금액이 그 공사에 기록된 합계(정가 550,000원, 할인 적용 시 할인 반영 합계)와 같으면 상태를 '입금 완료'로 바꾼다. 항목이 비어 있거나 입금액이 기록된 합계와 다르면 상태를 바꾸지 않고 누락 항목 또는 차액을 표시한다. 입력 내용은 메모와 함께 보존한다(D-15). | F10, AC-F10-2, AC-F10-3 |
| SR-FEE-04 | 이미 '입금 완료'인 공사에 입금 확인을 다시 기록하려 하면 중복 기록을 만들지 않고 안내한다. 같은 공사에 대한 동시·중복 요청은 하나만 성립시킨다. | F10, AC-F10-3, R-9 |
| SR-FEE-05 | 세금계산서 발행 여부와 발행일을 기록한다(입금 전·후 모두 가능). 시스템은 세금계산서를 발행하지 않는다. | F10, 용역비, Out of Scope 11 |
| SR-FEE-06 | 납품 후 가정값·착공일 변경으로 다시 출력해도 용역비 금액과 상태는 바뀌지 않고 추가 용역비를 만들지 않는다. | F10, AC-F10-4 |
| SR-FEE-07 | 의뢰 취소 처리: (가) 납품 이력이 없고 '입금 완료'이면 취소를 기록하면서 환불 요청일을 남기고, 요청일로부터 7일 이내에 입금액(그 공사에 기록된 합계) 전액을 환불한다. 관리자가 환불일을 기록하면 상태가 '환불'이 된다. (나) 납품 이력이 없고 '미입금'이면 취소를 기록해 상태를 '취소'로 바꾼다. (다) 납품 이력이 한 번이라도 있으면 환불·취소로 처리하지 않고 "납품 후에는 환불할 수 없다"를 안내하며 상태는 그대로 둔다. | F10, AC-F10-5, AC-F10-6 |
| SR-FEE-08 | 환불 요청이 기록된 뒤에는 환불이 끝나기 전에도 최종 출력을 허용하지 않는다. '환불'·'취소' 공사는 출력하지 않는다. 환불 요청과 최종 출력이 동시에 요청되면 먼저 기록된 쪽이 성립하고 나머지는 거부한다. | F10, AC-F10-6 |
| SR-FEE-09 | 환불 요청일로부터 7일 기한에 가까워졌거나 넘겼는데 환불일이 기록되지 않은 건을 관리자 화면(대시보드)에 표시한다. 임박 기준은 기한 2일 전이다(D-8). | F10, AC-F10-5 |
| SR-FEE-10 | 용역비 내역 화면에 공급가액, 부가세, 합계(정가 550,000원, 할인 적용 시 할인율과 할인 반영 합계), 상태, 세금계산서 발행 여부·발행일, 입금일, 입금자명, 입금액, 환불일(환불이면)을 보여 준다. | F10, AC-F10-2, AC-F10-5 |
| SR-FEE-11 | 카드번호·계좌 인증 정보 등 금융 인증 정보를 이 메뉴의 화면·서버·로그 어디에도 저장하거나 남기지 않는다. 저장 대상은 입금일·입금자명·입금액·세금계산서 발행 여부·발행일·환불일·메모뿐이다. | F10, 보안 |
| SR-FEE-12 | 모든 용역비 상태 변경과 입금·환불·세금계산서 기록을 관리자·시각·이전/이후 상태와 함께 이력으로 남긴다. | 보안 이력 |
| SR-FEE-13 | 용역비 상태와 납품 이력이 맞지 않는 경우(예: '환불'인데 납품 이력 있음)와 입금 확인 중복 기록 시도를 감지해 관리자에게 즉시 알린다. | R-9, 모니터링 |
| SR-FEE-14 | 공사를 만들 때 같은 사업자등록번호(숫자 10자리로 정규화)의 이전 공사를 보고 할인을 정한다. 직전 납품일부터 새 공사 생성일까지 180일 이내(180일 포함)이고 직전 건이 '입금 완료'면 10%, 180일 이내로 이어진 연속 3번째 공사부터 15%다. 환불·취소 공사와 납품 이력이 없는 공사는 이전 공사로 세지 않는다. 소개 보상 1건당 5%를 더하고 합계는 20%를 넘지 않는다. 할인액은 공급가액의 내림 값이며 비율·기간·상한은 설정 값이다. 새 공사 생성일보다 나중에 납품된 공사는 이전 공사로 세지 않는다. 소개 크레딧은 소개받은 업체의 첫 용역비가 '입금 완료'일 때 1건당 1개이고, 쓴 공사가 환불·취소되면 돌아온다. 복제 공사는 원본의 사업자등록번호로 할인한다. 금액은 공사 생성 때 정하고, **'미입금'이고 납품 전이며 환불 요청·환불·취소가 아닌 동안에만** 사업자등록번호·소개 업체 변경 또는 관리자의 '할인 다시 계산'으로 다시 정할 수 있다(변경 이력 기록). 입금·납품 뒤에는 기록된 금액이 바뀌지 않는다(SR-FEE-06). | `docs/RETENTION.md` |
| SR-FEE-15 | 업체 식별 키는 사업자등록번호다. 화면·로그에서는 뒤 5자리를 가려 표시한다. 재의뢰율(180일)·재의뢰 간격·소개율은 공사·납품 기록에서 계산하며, 관찰 기간이 지나지 않은 업체는 재의뢰율 분모에서 뺀다. | `docs/RETENTION.md` |

- 보존: 공사 종료 후 5년 보존, 이후 삭제. 용역비 이력도 같은 5년이며 법정 보존 기간이 더 길면 그 기간을 따른다(D-7).
- 입력 원본 파일은 수정하지 않는다.

## 6. 산정 로직·계산 규칙

모든 수치는 착공일, 공정별 착수·완료일차, 인원·장비 가정값에서 수식으로 계산한다. 같은 입력과 같은 가정값이면 결과는 항상 100% 같다(재현성). 엑셀 시제품의 계산식을 그대로 따른다.

### 6.1 보할

공정 i의 보할 w_i는 공정 순공사비 D_i를 전체 순공사비로 나눈 값이다.

```latex
w_i = \frac{D_i}{\sum_j D_j} \times 100
```

### 6.2 구간별 진도율

공정 i의 착수일 S_i, 완료일 E_i, 구간 k의 시작일 s_k, 종료일 e_k일 때 구간 진도율 p_{i,k}는 겹치는 달력일 수에 비례한다.

```latex
p_{i,k} = w_i \times \frac{\max\left(0,\ \min(E_i, e_k) - \max(S_i, s_k) + 1\right)}{E_i - S_i + 1}
```

구간은 착공일이 속한 달의 상순(1~15일)부터 상순·하순(16일~말일)을 번갈아 만든다.

### 6.3 작업일수

공정의 작업일수 ND_i는 착수일부터 완료일까지의 월~금 일수에서 공휴일을 뺀 값이다.

### 6.4 직종별 인일 산정(우선순위 순)

| 순서 | 방식 | 계산 | 표시 |
| --- | --- | --- | --- |
| 1 | 내역서 수량 | 내역서 '노무비' 행의 수량(인)을 그대로 사용 | 내역서 |
| 2 | 노무비 환산 | 인일 = 반올림(공종 노무비 × 직종 배분율 ÷ 노임단가) | 환산 |
| 3 | 생산성 | 인일 = 반올림(Σ 물량 × 생산성) × 직종 배분율 | 가정 |
| 4 | 직접 지정 | 인원/일 × 작업일수 | 가정 |

환산·생산성·직접 지정 인일에는 '가정' 표시와 근거 문구를 남긴다. 생산성 방식에서 직종별로 나눌 때 반올림 오차는 보통인부에 반영해 공정 총량을 보존한다.

### 6.5 구간별 연인원 배분

공정 i의 구간 k까지 누적 작업일수 비율 c_{i,k}를 구하고, 누적값을 반올림한 차이를 구간 값으로 쓴다. 모든 구간 값이 정수이고 합이 L_i와 같다.

```latex
c_{i,k} = \frac{ND(S_i,\ \min(E_i, e_k))}{ND_i}, \qquad x_{i,k} = \mathrm{round}(L_i\, c_{i,k}) - \mathrm{round}(L_i\, c_{i,k-1})
```

직종별 구간 연인원은 모든 공정의 x_{i,k}를 더한 값이다.

### 6.6 장비 대·일

- 내역서 장비(HR 단위)는 대·일 = 올림(HR ÷ 8). 예: 크레인 18HR → 3대·일.
- 가정 장비는 대수 × 일수. 일수를 '작업일수 전체'로 지정하면 해당 공정의 ND_i를 쓴다.
- 구간 배분은 6.5절과 같다.

### 6.7 일평균 투입인원

구간 일평균 = 구간 인원 소계 ÷ 구간의 공기 내 작업일수. 작업일수가 0이면 빈칸.

## 10. 가정·제약·리스크

### 10.1 가정(PRD 7장)

- 공사기간은 달력일 기준이고, 근무일은 주5일(월~금)에서 공휴일을 뺀다.
- 보할은 집계표의 직접공사비(재료비+노무비+경비) 기준이다. 간접노무비·법정경비·일반관리비·이윤은 배분하지 않는다.
- 내역서는 조달청 공고문에 첨부된 양식을 따르며 공고마다 다를 수 있다.
- 착공일은 계약 후 확정되며, 그 전에는 가정일을 쓴다.
- 자동 산정 결과는 초안이며 가정이 들어간 수치는 사람이 확인한다.
- 공휴일 목록은 연 1회 수동 갱신한다.
- 업체는 공고번호·내역서·계약·기술인 정보 등을 관리자에게 전달하고, 시스템에는 접근하지 않는다.
- 용역비는 납품 후 무통장입금(후불)으로 받고, 세금계산서는 시스템 밖에서 발행한다.

### 10.2 제약

- 올케어솔루션·올케어안전플랫폼과 무관한 별도 웹 서비스(웹 브라우저), 자체 주소(도메인). 다른 서비스의 코드·계정·결제·데이터에 의존하지 않는다(SR-PL-05).
- 입력 xlsx·pdf·API, 출력 xlsx·pdf만.
- 용역비 입금은 관리자 수기 기록만 하고 온라인 결제와 은행·PG 자동 연동을 만들지 않는다.
- 서버 비용 추가 없음(같은 NHN Cloud 서버), Supabase는 무료 요금제로 시작(자동 백업 없음, 백업은 서버에서 별도 마련), 공사 1건 500MB, 합본 100MB. 서비스 주소는 chakgong.allcaresolution.net.
- 주민등록번호·주소·계좌번호는 필요한 서류에만 쓰고 수집을 최소화한다.
- 검증을 통과하지 못하면 출력할 수 없다.

## 12. 후속 요구(1차 범위 밖, 번호 미부여)

| 차수 | 항목 |
| --- | --- |
| 2차 (Should) | 대공종 분할 규칙 설정, 생산성 방식 인일 산정 UI, 최대 인원 경고, 위치별 구간 연동, 실적 기반 기준정보 보정, 제출서류 체크리스트, 한글 금액 표기, 문서번호 자동 부여, 첨부 누락 경고, 가정 비중 보고, 공고 조건 점검, 변경 이력 조회 화면 |
