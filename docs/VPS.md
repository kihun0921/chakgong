# 착공계·공정표·인원장비투입계획 자동화 VPS (Value Proposition Sheet)

PRD 이전 단계 문서. VPS는 Value Proposition Sheet(가치 제안서)다.

## 1. 가치 제안

공고번호와 내역서만 넣으면 착공 서류 묶음이 틀린 곳 없이 나오고, 담당자는 서류를 베끼는 대신 일정과 가정을 판단하는 데 시간을 쓴다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 낙찰 후 착공 서류 15종을 맞춰 내야 하는 업체(시공사). 서류는 관리자가 맡아 작성해 납품한다 |
| 해결하는 문제 | 같은 값을 서류마다 다시 적다 생기는 수치 불일치, 수작업 산정 |
| 제품 | 착공계 자동화 프로그램. 별도 서비스로 운영하고 올케어솔루션 홈페이지에는 '착공계 작성' 메뉴(링크)만 단다. 관리자가 작성해 업체에 납품하는 용역으로 제공하고, 용역비는 납품 후 무통장입금으로 받는다 |
| 핵심 이점 | 공고번호·내역서 입력만으로 공정표, 투입계획, 착공 서류 묶음을 만들고 검증까지 마친다 |
| 현재 대안 | 내역서를 보며 엑셀·문서 서식으로 서류마다 수작업 |
| 차이 | 내역서와 모든 서류가 연결돼, 착공일이나 가정을 바꾸면 전체가 다시 계산된다 |

## 2. 고객 세그먼트

서비스를 받는 쪽은 낙찰 후 착공 서류를 제출해야 하는 업체이고, 시스템을 쓰는 사람은 이를 맡아 작성해 납품하는 관리자(1\~3명)이다. 업체가 스스로 시스템에서 작성하는 경우는 극히 드물다고 보고, 업체는 시스템에 접근하지 않는다.

| 구분 | 처한 상황 | 원하는 것 |
| --- | --- | --- |
| 업체(고객, 시스템 비사용자) | 낙찰 후 짧은 기간에 착공 서류 15종을 맞춰 내야 하고, 제출 전에 수치가 맞는지 불안하다 | 틀리지 않은 서류 묶음을 기한 안에 받고, 용역비는 납품 후 무통장입금으로 지급한다 |
| 관리자(시스템 사용자) | 업체에서 의뢰받은 서류를 빠르고 틀리지 않게 만들어 납품해야 하고, 직종·노임·장비·양식 기준도 직접 관리한다 | 빠르게 서류 묶음을 만들고, 기준값을 한 곳에서 갱신하며, 납품·입금 현황을 한눈에 본다 |

대상 공사는 조달청(나라장터) 시설공사이며, 기계설비에서 시작해 건축·토목·조경·전기로 넓힌다.

## 3. 고객 프로필 (Jobs·Pains·Gains)

고객(업체)의 가장 큰 고통은 같은 값을 서류마다 손으로 다시 적다가 수치가 어긋나는 것이다. 이 장의 Jobs·Pains·Gains는 서비스를 받는 업체 기준이고, 이를 맡아 해결하는 사람은 관리자다.

**해야 할 일 (Jobs)**

- 착공 서류 15종을 발주기관에 제출한다.
- 내역서를 보고 예정공정표와 인원·장비투입계획을 만든다.
- 계약·기술인 정보를 각 서류에 맞게 기재한다.
- 발주기관·계약 유형에 맞는 양식으로 서류를 갖춘다.

**고통 (Pains)**

- 샘플 착공계에서 준공일이 서류마다 2029.3.9와 2029.03.10으로 다르고, 발주처가 군청과 조달청으로 달리 적혀 있다.
- 금액 검산과 직종별 인원·장비 산정을 사람이 직접 한다.
- 내역서 양식이 공고마다 다르고, 계약 유형(국가·지방)에 따라 문안이 달라 매번 손본다.
- 내역서나 착공일이 바뀌면 공정표와 서류를 처음부터 다시 만든다.
- 주민등록번호·계좌번호가 든 서류를 여러 파일에 반복해서 기재한다.

**기대 (Gains)**

- 서류 안의 수치가 서로 어긋나지 않는다.
- 입력부터 초안까지 짧은 시간에 끝난다.
- 일정이나 가정을 바꾸면 결과가 바로 반영된다.
- 한 번 입력한 정보를 모든 서류에 다시 쓴다.
- 제출 전에 어긋난 곳을 확인할 수 있다.

## 4. 제품·서비스

제품은 착공계 자동화 프로그램 하나이고(별도 서비스, 홈페이지에는 메뉴만 연결), 관리자가 입력 두 가지에서 서류 세 묶음을 만들어 업체에 납품한다. 용역비는 서류 일체 1건 공급가액 500,000원(부가세 포함 550,000원)이며, 납품 후 업체가 무통장입금하면 관리자가 입금을 확인해 기록한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 나라장터 입찰공고 API 또는 파일 첨부, 내역서(xlsx) |
| 계산 | 보할·진도율, 직종별 인원, 장비 투입 |
| 산출물 1 | 예정공정표(xlsx) |
| 산출물 2 | 인원 및 장비투입계획표(xlsx) |
| 산출물 3 | 착공계 서류 합본(PDF): 공문, 착공신고서, 선임계류, 조직도, 사진첩, 노무비 합의서, 확약서 등 |
| 검증 | 집계표 대비 금액 차이, 서류 간 일치, 공기 초과 경고 |
| 적용 공종 | 기계설비·건축·토목·조경·전기 |

## 5. 고통 해소·이점 창출

3장의 고통과 기대마다 제품이 해 주는 일을 짝지었다. 마지막 열은 PRD의 기능 번호다.

| 고객의 고통·기대 | 제품이 해 주는 일 | PRD 기능 |
| --- | --- | --- |
| 서류 간 수치·표기 불일치 | 값을 한 번 입력해 모든 서류에 재사용하고, 서류 간 일치를 검사한다 | F5, F6 |
| 금액 검산·인원·장비 수작업 | 집계표 대비 차이를 자동 검산하고, 내역서 노무수량에서 인원·장비를 산정한다 | F3, F4, F6 |
| 공고마다 다른 양식·계약 유형별 문안 | 공고 첨부 양식을 인식하고 안 되면 열 매핑, 계약 유형별 템플릿으로 전환한다 | F1, F5 |
| 내역서·착공일 변경 시 재작성 | 착공일과 가정을 바꾸면 일정·진도율·인원이 3초 이내에 다시 계산된다 | F2, F3, F4 |
| 개인정보 서류 반복 기재 | 기술인 정보를 한 번 입력해 재사용하고, 암호화·마스킹한다 | F5, F9 |
| 짧은 시간에 초안 | 입력부터 초안 출력까지 5분 이내 | F1\~F7 |
| 제출 전 확신 | 불일치·공기 초과를 경고하고, 검증을 통과해야 출력한다 | F6 |

## 6. 차별점

현재 방식(내역서를 보며 서류마다 수작업)과 비교한 차별점은 네 가지다. 다른 제품과의 비교는 이 문서에서 하지 않는다.

1. **연결된 계산**: 내역서, 공정표, 투입계획, 서류가 하나의 입력에서 나온다. 착공일이나 가정을 바꾸면 전체가 다시 계산된다.
2. **조달청 시설공사에 맞춘 서류 구성**: 샘플 착공계 15종, 공고 첨부 내역서 양식, 국가·지방 계약 유형별 문안을 전제로 설계했다.
3. **가정의 투명성**: 인원·장비 값에 내역서 수량, 환산, 가정 표시와 근거를 붙여 관리자와 업체가 어디까지 믿을지 알 수 있다.
4. **관리자 납품 방식, 별도 서비스**: 업체는 시스템을 쓰지 않고 완성된 서류만 받는다. 올케어안전플랫폼처럼 별도 서비스로 운영하며, 올케어솔루션 홈페이지에는 메뉴(링크)만 단다.

## 7. 증거와 검증할 가정

가치 제안은 엑셀 시제품으로 일부만 입증됐고, 시간 절감 효과와 가정 인원의 현실성은 아직 검증하지 못했다.

| 가정 | 현재 근거 | 검증 방법 |
| --- | --- | --- |
| 값을 한 번 입력해 재사용하면 서류 간 불일치가 사라진다 | 샘플에서 준공일·발주처 불일치 확인 | 서류 간 일치 검증(PRD AC-F5-1, AC-F6-3) |
| 내역서 기반 자동 계산이 수작업 결과와 맞는다 | 엑셀 시제품에서 순공사비 합계 622,764,021원, 집계표와 차이 0원 | 금액·보할·인원 검증(PRD AC-F2-2, AC-F3-1, AC-F4-2) |
| 가정 인원·장비가 현실에 가깝다 | 시제품 가정값뿐, 실제 실적 없음 | 완료 공사 실적과 비교해 보정(PRD 가설 H4), 현장 검토 |
| 5분 이내 초안으로 시간이 줄어든다 | 목표값만 있고 현재 작성 시간은 측정 전 | 현재 작성 시간·보완 횟수 측정 |
| 나라장터 API로 공고 정보와 내역서를 받는다 | 방식은 확정(API 우선, 실패 시 파일 첨부), API 키 확보 완료 | API 이용 조건 확인, 실패 시 파일 첨부 |
| 직접시공계획서까지 한 묶음으로 낼 수 있다 | 양식 미수령(수령 전에는 업로드 첨부로 처리) | 양식 수령 후 추가 |
