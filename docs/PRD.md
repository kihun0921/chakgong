# 착공계·공정표·인원장비투입계획 자동화 PRD v0.1

- Owner 팀: 착공계 자동화 프로그램 개발, 별도 서비스로 운영하며 올케어솔루션 홈페이지에 메뉴로 연결 (작성: EGIGAE 7기 권기훈) — 팀명 없음
- 최종 업데이트: 2026-10-17
- 문서 체인: VPS(왜) → **PRD(무엇을, 이 문서)** → SRS(어떻게, 이 PRD를 기준으로 작성한 SRS v1.0)
- 이 문서에서 제안했던 값은 2026-10-17에 모두 확정했다. 같은 날 제공 방식을 '업체가 직접 쓰는 도구'에서 '관리자가 작성해 업체에 납품하는 용역'으로 바꾸고, 용역비는 납품 후 무통장입금(후불)으로 받는 것으로 정리했다(1장 '제공 방식', 부록 10~13번). 또한 올케어안전플랫폼과 같은 방식으로, 올케어솔루션 홈페이지에는 메뉴(링크)만 달고 별도 서비스로 운영하는 것으로 정했다(1장 '제공 방식', 부록 14번). 확정 후에도 확보·확인이 남은 것은 부록에 조치로 적었다.
- 이 PRD는 개발 착수용으로 Acceptance Criteria(3장), KPI(1장), 비기능 수치(5장), 제약 조건·Out of Scope(7장), DoD 자가 점검(10장)을 채웠다.

## 1. 개요·목표

### 제공 방식 (확정)

이 제품은 업체가 직접 쓰는 도구가 아니라, **관리자가 관리자 계정으로 로그인해 착공 서류를 작성하고, 완성한 서류를 업체에 납품한 뒤 용역비를 받는 용역 형태**가 주된 사용 방식이다.

- 업체(고객사)는 이 시스템에 로그인하지 않는다. 관리자가 업체에서 받은 공고번호·내역서·계약 정보로 공사를 만들고, 완성된 파일(xlsx·PDF)을 업체에 전달한다.
- 용역비는 납품 후 업체가 무통장입금으로 보낸다(후불). 시스템은 입금을 직접 받지 않고, 관리자가 입금을 확인해 기록한다.
- 세금계산서는 시스템 밖(기존 방식)에서 발행하고, 시스템에는 발행 여부와 발행일만 기록한다.
- 업체가 스스로 시스템에서 작성하는 경우는 극히 드물다고 보고 이번 범위에서 제외한다(7장 Out of Scope 12번).
- **별도 서비스로 운영, 홈페이지에는 메뉴만 연결(확정)**: 올케어솔루션 홈페이지(단말기 렌탈·내역 신청 전용)에는 '안전보건관리계획서'를 작성하는 올케어안전플랫폼과 이 프로그램을 메뉴(링크)로만 단다. 서비스마다 별도로 운영하며, 올케어안전플랫폼이 별도 회원가입·결제를 쓰듯 이 프로그램도 올케어솔루션·올케어안전플랫폼의 로그인·결제·데이터와 연동하지 않는다. 이 프로그램은 자체 관리자 로그인과 무통장입금 기록을 쓴다. 홈페이지에 메뉴를 다는 일은 1차 출시 뒤 홈페이지 쪽에서 하며 1차 범위 밖이다(Out of Scope 13번).

### 문제 정의 (Pain 지표 포함)

### 용역비 (확정)

- **착공계 서류 일체 1건: 공급가액 500,000원, 부가세 10% 50,000원, 입금액 550,000원(부가세 포함).** 공사 1건의 착공 서류 묶음(예정공정표, 인원·장비투입계획표, 착공계 합본 PDF 등)을 만들어 납품하는 값이다. 업체는 550,000원을 무통장입금한다.
- 서버 비용은 추가로 발생하지 않는다(올케어안전플랫폼과 같은 NHN Cloud 서버에서 운영). Supabase는 무료 요금제로 시작한다(확정). 무료 한도에 가까워지면 그때 유료 전환 여부를 정한다(5장).
- **후불(확정)**: 납품(최종 출력)이 먼저이고, 입금은 납품 뒤에 받는다. 입금 여부와 상관없이 검증을 통과한 공사는 최종 출력할 수 있다.
- 입금은 관리자가 확인해 입금일·입금자명·입금액을 기록한다(F10). 이 메뉴는 결제 대행(PG)·카드 결제를 만들지 않는다.
- 세금계산서는 시스템 밖에서 발행하고(확정), 시스템에는 발행 여부와 발행일만 기록한다.
- 용역비는 공사 1건당 1회다. 납품 후 업체 요청으로 가정값·착공일을 바꿔 다시 작성·납품해도 추가 용역비는 없다(확정).
- 환불: 서류 일체를 최종 출력(납품)하기 전에 의뢰가 취소되고 이미 입금된 경우, 취소일로부터 7일 이내에 입금액 전액(550,000원)을 환불한다. 한 번이라도 최종 출력(납품)한 뒤에는 환불하지 않는다(확정, 기존 환불 정책을 무통장입금 방식에 맞춰 적용).
- 입금·미수 현황은 관리자 대시보드에서 본다(F11).

- 대상 공사: 조달청(나라장터) 시설공사, 기계설비·건축·토목·조경·전기

## 3. 사용자 스토리와 수용 기준(AC)

Must 기능(F1~F11)마다 Given / When / Then으로 **정상 2개 + 실패 1개**를 둔다(F10은 정상 4개 + 실패 2개). 수치는 엑셀 시제품 검증 결과(중대범죄수사청 사무환경 조성사업(기계) 내역서 기준)를 썼다. 모든 동작의 주체는 관리자다.

### F1 공고·내역서 입력

**Story**: 관리자로서, 공고번호만 넣으면 공사 정보와 내역서가 들어오길 원한다. 그래서 공사 정보를 다시 타이핑하지 않는다.

- **AC-F1-1 (정상)** Given 유효한 공고번호, When 입력하고 조회하면, Then 공사명·공사관리번호·수요기관·공사기간이 자동 입력되고 첨부 내역서를 수신한다.
- **AC-F1-2 (정상)** Given .xlsx 내역서(20MB 이하), When 업로드하면, Then 집계표의 공종별 재료비·노무비·경비·합계와 내역서의 노무 행(직종·수량·노임단가)이 표로 추출되고, 관리자가 확인·수정해 확정해야만 다음 단계로 넘어간다. 시트·머리글을 인식하지 못하면 열 매핑으로 지정할 수 있다.
- **AC-F1-3 (실패)** Given 나라장터 API 장애 또는 호출 실패, When 조회가 실패하면, Then 실패 사유를 안내하고 입력한 값을 잃지 않은 채 파일 첨부·수동 입력으로 끝까지 진행할 수 있다.

### F2 공정 구성·일정

**Story**: 관리자로서, 내역서 공종이 공정표 행이 되고 일정만 정하면 되길 원한다. 그래서 공정표를 처음부터 짜지 않는다.

- **AC-F2-1 (정상)** Given 착공일 2026-11-02, 공기 70일, 공휴일 12/25·1/1, When 준공일을 계산하면, Then 준공예정일은 2027-01-10이다.
- **AC-F2-2 (정상)** Given 확정된 집계표, When 공정 목록을 만들면, Then 공종 계층(대공종·세부공정)이 유지되고, 금액이 0원인 공종은 금액 없이 협조 구간으로만 표시되며, 공정표 순공사비 합계는 622,764,021원으로 집계표와 차이가 0원이다.
- **AC-F2-3 (실패)** Given 공정 완료일차를 75로 입력한 상태에서 공기가 70일일 때, When 검증하면, Then 경고가 표시되고 출력이 차단된다.

### F3 보할·진도율

**Story**: 관리자로서, 금액 비율과 구간별 진도율이 자동 계산되길 원한다. 그래서 공정표를 손으로 검산하지 않는다.

- **AC-F3-1 (정상)** Given 착공일 2026-11-02, 공기 70일, When 계산하면, Then 보할 합계는 100.00이고 구간 진도율 누계는 2.99 → 34.17 → 67.34 → 95.98 → 100.00이다.
- **AC-F3-2 (정상)** Given 착공일을 2026-11-16으로 변경, When 재계산하면, Then 구간 머리글·일정·진도율·인원이 3초 이내 갱신되고 합계는 변하지 않는다.
- **AC-F3-3 (실패)** Given 공정 금액 합이 집계표와 달라 진도율 누계가 100.00%가 아닐 때, When 출력하려 하면, Then 출력이 막히고 어느 공정·구간에서 어긋났는지 표시된다.

### F4 인원·장비 투입계획

**Story**: 관리자로서, 내역서 노무수량에 맞는 인원 계획을 받고 가정은 구분해 보고 싶다. 그래서 업체에 납품할 때 어디까지 믿을지 안다.

- **AC-F4-1 (정상)** Given 내역서 노무 행에 직종별 수량(배관공 급수급탕 44인, 오배수 53인, 철거 4인)이 있을 때, When 산정하면, Then 그 수량이 그대로 투입수에 포함되고 산정 방식이 '내역서'로 표시된다.
- **AC-F4-2 (정상)** Given 시제품 가정값, When 산정하면, Then 연인원 1,338인일·장비 296대·일이고 모든 구간 값이 정수이며 구간 합이 공정 총량과 같다. 환산·생산성·직접 지정으로 만든 값은 '가정'으로 색과 표기가 구분되고 근거 문구가 남는다.
- **AC-F4-3 (실패)** Given 공정표·투입계획표·산정근거의 연인원 합계가 서로 다를 때, When 출력하려 하면, Then 출력이 막히고 어긋난 항목이 표시된다.

### F5 착공계 서류 묶음

**Story**: 관리자로서, 착공 서류 15종을 한 번에 만들고 싶다. 그래서 같은 값을 반복 입력하지 않는다.

- **AC-F5-1 (정상)** Given 착공일을 바꾸고 전체 서류를 다시 생성, When 확인하면, Then 착공신고서·안전보건관리책임자 선임서·공정표 머리부의 준공일이 모두 같은 계산값(착공일 + 공사기간 − 1)이다.
- **AC-F5-2 (정상)** Given 업체의 기술인 정보를 1회 입력, When 서류를 생성하면, Then 선임계·재직증명서·사용인감신고서·선임서·조직도에 모두 반영되고, 생성 서류와 업로드 첨부 PDF가 지정 순서(기본은 제출서류 목차 순서)로 쪽번호·목차가 포함된 한 파일로 합본된다.
- **AC-F5-3 (실패)** Given 계약 유형(국가·지방) 또는 필수 입력값이 비어 있을 때, When 서류를 생성하려 하면, Then 생성이 막히고 누락된 항목 목록이 표시된다. 제출일은 비워 두어도 생성된다.

### F6 검증

**Story**: 관리자로서, 업체에 납품하기 전에 수치 불일치가 없는지 확인하고 싶다. 그래서 업체의 반려·보완 요구를 줄인다.

- **AC-F6-1 (정상)** Given 집계표 차이 0원, 진도율 누계 100.00%, 연인원 합계 일치, 서류 간 값 일치, When 검증하면, Then '통과'로 표시되고 출력이 가능해진다.
- **AC-F6-2 (정상)** Given 가정값을 수정, When 다시 검증하면, Then 3초 이내 결과가 갱신된다.
- **AC-F6-3 (실패)** Given 한 서류의 준공일이 다른 서류와 다를 때(예: 2029.3.9와 2029.03.10), When 서류 간 교차 검사를 하면, Then 어떤 서류의 어떤 항목이 다른지 표시되고 출력이 차단된다.

### F7 출력(납품 파일 생성)

**Story**: 관리자로서, 엑셀과 PDF로 받고 싶다. 그래서 업체에 납품하거나 직접 손볼 수 있다.

- **AC-F7-1 (정상)** Given 검증을 통과한 결과, When xlsx로 출력하고 Excel(Windows)·LibreOffice에서 열면, Then 수식 오류가 0건이고 재계산되며 산정근거·검산 시트가 포함된다.
- **AC-F7-2 (정상)** Given 검증을 통과한 결과, When PDF로 출력하면, Then 공정표와 투입계획표가 각각 A3 가로 한 페이지로 나오고 착공계 합본 PDF가 생성된다. 800행 내역서 기준 파싱·계산·출력은 30초 이내다.
- **AC-F7-3 (실패)** Given 합본에 넣을 업로드 PDF 중 하나가 손상돼 있을 때, When 합본하면, Then 손상된 파일을 지목해 알리고 나머지 입력·결과는 보존된 채 다시 시도할 수 있다.

### F8 공사·기준정보 관리

**Story**: 관리자로서, 의뢰받은 공사를 저장해 두고 기준값을 한 곳에서 관리하고 싶다. 그래서 기준이 바뀔 때 코드를 고치지 않는다.

- **AC-F8-1 (정상)** Given 관리자가 직종·노임·장비·생산성·일정 템플릿·공휴일을 수정, When 저장하면, Then 코드 수정 없이 이후 계산에 반영된다.
- **AC-F8-2 (정상)** Given 저장된 공사, When 불러오거나 다른 공사로 복제하면, Then 입력·가정값·결과가 이어지고 원본은 바뀌지 않는다.
- **AC-F8-3 (실패)** Given 관리자 권한이 없는 사용자, When 기준정보를 수정하려 하면, Then 권한 오류가 표시되고 값은 바뀌지 않는다.

### F9 관리자 로그인·권한

**Story**: 관리자로서, 관리자 계정으로 로그인해 모든 기능을 쓰고 싶다. 그래서 공사·개인정보·용역비 자료가 다른 사람에게 노출되지 않는다.

- **AC-F9-1 (정상)** Given 관리자 계정, When 로그인하면, Then 착공계 프로그램 화면이 열린다.
- **AC-F9-2 (정상)** Given 관리자, When 착공계 프로그램을 쓰면, Then 모든 공사의 조회·작성, 기준정보 편집, 용역비·입금 관리, 대시보드 조회가 가능하다.
- **AC-F9-3 (실패)** Given 로그인하지 않았거나 관리자 권한이 없는 사용자(업체 포함), When 착공계 메뉴나 공사 화면 주소로 직접 접근하면, Then 접근이 거부되고 자료는 노출되지 않으며 시도 이력이 남는다.

### F10 용역비·입금 관리 (무통장입금 기록)

**Story**: 관리자로서, 납품한 공사의 용역비 입금을 한곳에서 기록·확인하고 싶다. 그래서 어느 업체가 입금했고 안 했는지 따로 정리하지 않는다.

- **AC-F10-1 (정상)** Given 검증을 통과한 공사 1건, When 관리자가 최종 출력해 서류 일체를 업체에 납품하면, Then 납품(최종 출력) 이력이 기록되고 용역비 550,000원(공급가액 500,000원 + 부가세 50,000원)은 '미입금'으로 남는다. 입금 전에도 최종 출력할 수 있다.
- **AC-F10-2 (정상)** Given 납품했고 용역비가 '미입금'인 공사, When 관리자가 무통장입금을 확인해 입금일·입금자명·입금액 550,000원을 기록하면, Then 상태가 '입금 완료'로 바뀌고 공급가액, 부가세, 입금액, 입금일, 입금자명, 세금계산서 발행 여부·발행일이 표시된다.
- **AC-F10-4 (정상)** Given 납품과 입금이 끝난 공사, When 업체 요청으로 관리자가 가정값이나 착공일을 바꿔 다시 출력하면, Then 추가 용역비 없이 출력되고 용역비 금액·상태는 바뀌지 않는다.
- **AC-F10-5 (정상)** Given 입금은 됐으나 서류를 아직 최종 출력하지 않은 공사, When 관리자가 의뢰 취소를 기록하면, Then 취소일로부터 7일 이내에 입금액 550,000원을 전액 환불하고, 관리자가 환불일을 기록하면 상태가 '환불'로 바뀌어 환불일이 표시된다. 입금이 없었다면 '취소'로 기록된다.
- **AC-F10-6 (실패)** Given 서류 일체를 한 번이라도 최종 출력(납품)한 공사, When 관리자가 취소·환불을 기록하려 하면, Then 환불로 처리되지 않고 "납품 후에는 환불할 수 없다"는 안내가 표시되며 용역비 상태는 그대로 유지된다.
- **AC-F10-3 (실패)** Given 입금 확인을 기록하는데 입금일·입금자명·입금액 중 하나가 비어 있거나 입금액이 550,000원이 아닐 때, When 저장하려 하면, Then '입금 완료'로 바뀌지 않고 누락 항목 또는 차액이 표시된다. 이미 '입금 완료'인 공사에 입금 확인을 다시 기록하려 하면 중복 기록이 만들어지지 않는다.

### F11 관리자 대시보드

**Story**: 관리자로서, 용역비 입금·미수와 이용 현황을 한 화면에서 보고 싶다. 그래서 서비스 상태와 매출을 따로 모으지 않는다.

- **AC-F11-1 (정상)** Given 관리자가 대시보드를 열면, When 기간을 고르면, Then 용역비 건수, 금액 합계(공급가액·부가세·합계), 상태별(미입금·입금 완료·환불·취소) 건수, 미입금 금액 합계(미수금)가 표시된다.
- **AC-F11-2 (정상)** Given 관리자가 대시보드를 열면, When 운영 지표를 보면, Then 파싱 성공률, 초안 생성 소요 시간, 검증 실패 유형별 건수, 나라장터 API 성공률이 표시된다.
- **AC-F11-3 (실패)** Given 관리자가 아닌 사용자, When 대시보드에 접근하면, Then 접근이 거부되고 용역비 내역이 노출되지 않는다.

## 4. 기능 요구사항(FR)

우선순위는 MoSCoW로 정했다. 1차 출시는 Must 전부, Should는 2차, Could는 3차다. 근거 열은 'VPS의 Pain 심각도 × 현재 대안(수작업)과의 격차'로 기회 우선도(상·중·하)를 매겼다. AOS/DOS는 기회 우선도(상/중/하)로 확정했다.

| 기능 | MoSCoW | 핵심 내용 | 기회 우선도 | 우선순위 근거(VPS Pain · 대안 대비 가치) |
| --- | --- | --- | --- | --- |
| F1 공고·내역서 입력 | Must | 공고번호 → 공사 정보·내역서 수신, 실패 시 파일 첨부·수동 입력, 열 매핑, 추출값 확인 | 상 | 모든 계산의 입력 원천. Pain '양식 다양성'. 수작업 재입력 대비 오류·시간 감소 |
| F2 공정 구성·일정 | Must | 내역서 공종 계층으로 공정 목록 자동 생성, 공종 유형 5종 선택, 착수·완료일차 입력, 0원 공종은 협조 구간 표시, 착공일·공기·공휴일 설정 후 준공일 계산 | 상 | 공정표의 뼈대. Pain '변경 시 재작성'. 엑셀 시제품에서 검증됨 |

| F5 착공계 서류 묶음 | Must | 공문, 착공신고서, 기술인 선임계류, 안전보건관리책임자 선임서, 조직도, 간지, 사진첩, 노무비 합의서, 확약서 생성. 공동수급체·기술인 1회 입력 재사용. 계약 유형별 템플릿 전환. 업로드 첨부와 합본 | 상 | Pain '서류 간 불일치', '개인정보 반복 기재'. 불일치의 직접 해결책 |
| F6 검증 | Must | 집계표 차이 0원, 공기 초과 경고, 서류 간 교차 일치, 연인원·장비 합계 일치 | 상 | Gain '제출 전 확인'. 업체의 반려·보완 요구 방지, 출력 차단 게이트 |
| F7 출력(납품 파일 생성) | Must | 공정표·투입계획표 xlsx(수식 유지), 산정근거·검산 시트, A3 가로 PDF, 착공계 합본 PDF | 중 | 발주기관 제출 형식이자 업체에 납품하는 결과물. 수식 유지로 수정 가능. 없으면 결과를 쓸 수 없어 Must |
| F8 공사·기준정보 관리 | Must | 공사별 저장·복제, 직종·노임·장비·생산성·일정 템플릿·공휴일 관리 | 중 | Pain '양식 다양성', 코드 수정 없는 양식·기준 교체 |
| F9 관리자 로그인·권한 | Must | 이 프로그램 자체의 관리자 계정 로그인, 관리자 권한. 다른 서비스(올케어솔루션·올케어안전플랫폼)의 로그인·계정과 연동하지 않음 | 중 | 개인정보 접근 통제, 별도 서비스로 독립 운영 |
| F10 용역비·입금 관리 | Must | 서류 일체 1건 용역비 550,000원(공급가액 500,000원 + 부가세) 기록, 후불(납품 후 입금), 무통장입금 확인 기록(입금일·입금자명·입금액), 세금계산서 발행 여부·발행일 기록, 납품 후 재작성은 추가 용역비 없음, 환불(납품 전만) 기록 | 상 | 용역 수익을 놓치지 않는 수단. 후불이라 미입금을 추적하지 못하면 미수금이 쌓인다. PG 연동 없이 기록만 하므로 구현이 작다 |
| F11 관리자 대시보드 | Must | 용역비 건수·금액(공급가액·부가세·합계)·상태별(미입금·입금 완료·환불·취소) 건수·미수금, 운영 지표(파싱 성공률, 초안 생성 시간, 검증 실패 유형, API 성공률) | 중 | 입금·미수와 서비스 상태를 관리자가 한 곳에서 확인. 없으면 미입금·장애를 알기 어렵다 |
| 2차 확장 | Should | 대공종 분할 규칙 설정, 생산성 방식 인일 산정, 최대 인원 경고, 위치별 구간 연동, 실적 기반 기준정보 보정, 제출서류 체크리스트, 한글 금액 표기, 문서번호 자동 부여, 첨부 누락 경고, 가정 비중 보고, 공고 조건 점검, 변경 이력 | 중~하 | 1차 사용 후 보정 항목 확정. 없어도 제출 가능하나 편의·신뢰도 향상 |
| 3차 확장 | Could | 선후행 관계로 일정 자동 산정, S-curve 진도율 배분 | 하 | 1차는 일차 직접 입력으로 충분 |
| 비목표 | Won't | 7장 'Out of Scope' 참고 | - | 범위 통제 |

F4의 인원 산정 순서(내역서 수량 → 노무비 환산 → 생산성 → 직접 지정)는 계산 규칙으로 1차에 모두 포함한다. 2차 확장의 '생산성 방식 인일 산정'은 생산성 값을 입력·관리하는 화면과 기능을 뜻하며, 1차에서는 기준정보에 생산성 값이 있을 때만 이 단계를 적용한다.

공종 확장(건축·토목·조경·전기)은 1차에 구조를 포함한다. 공종별 템플릿·기준정보를 채우는 순서는 개발 일정에서 정한다.

## 6. 데이터·인터페이스 개요

### 핵심 엔터티, 주요 필드

공사 1건당 9개 데이터 묶음을 저장한다. 입력 원본은 수정 없이 보관하고, 사용자가 바꾼 가정값만 별도로 기록한다. 공사 1건은 업체(시공사) 1곳의 의뢰 1건이다.

| 엔터티 | 주요 필드 | 출처 |
| --- | --- | --- |
| 공사 정보 | 공사명, 공사관리번호, 수요기관, 현장 주소, 추정금액, 공사기간(일), 착공일, 준공예정일 | 입찰공고, 관리자 입력 |
| 내역서 공종 | 공종코드, 공종명, 재료비, 노무비, 경비, 합계 | 집계표 |
| 내역서 품목 | 공종코드, 품명, 규격, 단위, 수량, 단가, 금액 | 내역서 시트 |
| 노무 라인 | 공종코드, 직종, 수량(인), 노임단가, 노무비 | 내역서 '노무비' 행 |
| 공정 | 공정키, 명칭, 상위 공정, 연결 공종코드, 금액, 착수일차, 완료일차, 비고 | 공정 구성 규칙, 관리자 입력 |
| 투입 산정 라인 | 공정키, 직종 또는 장비, 방식(수량/환산/생산성/가정), 배분율, 인일 또는 대·일, 근거 문구 | 계산 결과, 관리자 입력 |
| 기준정보 | 직종, 노임단가, 장비, 생산성(인일/EA), 일정 템플릿, 공휴일 | 관리자 입력 |
| 착공계 정보 | 의뢰 업체(시공사) 상호·대표자·사업자등록번호·주소·전화, 현장대리인, 건설기술인, 안전관리 담당자, 계약번호, 계약금액, 제출일, 공동수급체, 노무비 계좌 | 업체에서 받은 자료를 관리자가 입력 |
| 용역비 정보 | 공사 식별자, 용역비 상태(미입금·입금 완료·환불·취소), 공급가액(500,000원), 부가세(50,000원), 용역비 합계(550,000원), 세금계산서 발행 여부·발행일, 입금일, 입금자명, 입금액, 환불 요청일, 환불일, 메모 | 관리자 입력(무통장입금 확인) |

납품 이력(최종 출력 시각, 출력물)은 별도 입력 없이 최종 출력이 성공할 때 자동 기록된다. 환불 가능 여부는 이 이력으로 판단한다.

데이터 규칙: 금액은 원 단위 정수, 보할은 소수 둘째 자리 표시(내부 계산은 반올림하지 않음), 날짜는 yyyy-mm-dd 저장·yyyy.mm.dd 표시. 개인정보(주민등록번호·주소)와 금융정보(계좌번호)는 보호 대상.

### 제약 조건

반드시 지켜야 하는 울타리다.

**기술 제약**

- 올케어안전플랫폼·올케어솔루션과 무관한 별도 웹 서비스로 만들고 웹 브라우저에서 쓴다. 자체 주소(도메인)를 가지며, 다른 서비스의 코드·계정·결제·데이터에 의존하지 않는다. 올케어솔루션 홈페이지는 이 주소로 연결하는 메뉴만 단다.
- 입력은 xlsx(내역서)·pdf·나라장터 API, 출력은 xlsx·pdf만 쓴다(docx·hwp 없음).
- 출력 xlsx는 Excel(Windows)과 LibreOffice에서 수식 오류 없이 열려야 한다.
- 나라장터 API를 못 써도 파일 첨부만으로 끝까지 동작해야 한다.
- 용역비 입금은 관리자가 수기로 기록하고, 은행·PG 자동 연동과 온라인 결제를 만들지 않는다.
- 양식·계산 규칙·기준정보는 코드가 아니라 설정으로 바꿀 수 있어야 하고, 계산 로직에는 자동 테스트를 둔다.
- 입력 원본은 수정 없이 보관하고, 사용자가 바꾼 가정값만 따로 기록한다.

**운영 제약**

- 데이터는 클라우드에 저장하고 공사 종료 후 5년 보존한 뒤 삭제한다.
- 관리자 1~3명이 쓴다. 업체는 시스템을 쓰지 않는다. 공휴일 목록은 연 1회 수동 갱신한다.
- 근무일은 주5일(월~금)에서 공휴일을 뺀 일수, 보할은 직접공사비(집계표) 기준이다.
- 주민등록번호·주소·계좌번호는 필요한 서류에만 쓰도록 수집을 최소화하고, 화면에서는 마스킹하며 전체 값은 출력 PDF에만 표기한다.
- 자동 산정 결과는 초안이고, 가정이 들어간 수치는 사람이 확인한다. 검증을 통과하지 못하면 출력할 수 없다.
- 업체에서 받은 개인정보·계좌 정보는 서류 작성에만 쓰고, 납품 파일에만 전체 값을 표기한다.

**비용 제약**

- 공사 1건 저장 용량 500MB 이하, 합본 PDF 100MB 이하(확정).
- 서버 비용은 추가로 발생시키지 않는다(확정). 올케어안전플랫폼과 같은 NHN Cloud 서버에서 운영한다.
- Supabase는 무료 요금제로 시작한다(확정). 무료 한도(데이터베이스 500MB, 파일 1GB, 7일 무접속 시 일시 중지, 자동 백업 없음) 안에서 운영하고, 한도에 가까워지면 유료 전환을 정한다. 무료에는 자동 백업이 없으므로 일 1회 백업(RPO 24시간)은 이 서비스가 따로 마련해야 한다.
- 용역비는 서류 일체 1건 공급가액 500,000원, 입금액은 부가세 포함 550,000원(확정). 후불이고, 납품 후 재작성은 추가 용역비 없음.

### 가정

- 공사기간은 달력일 기준이고, 근무일은 주5일(월~금)에서 공휴일을 뺀다.
- 보할은 집계표의 직접공사비(재료비+노무비+경비) 기준이다. 간접노무비·법정경비·일반관리비·이윤은 배분하지 않는다.
- 내역서는 조달청 공고문에 첨부된 양식을 따르며 공고마다 다를 수 있다.
- 착공일은 계약 후 확정되며, 그 전에는 가정일을 쓴다.
- 자동 산정 결과는 초안이며, 가정이 들어간 수치는 사람이 확인한다.
- 업체는 공고번호·내역서·계약·기술인 정보 등을 관리자에게 전달하고, 시스템에는 접근하지 않는다.
- 용역비는 납품 후 무통장입금(후불)으로 받고, 세금계산서는 시스템 밖에서 발행한다.
